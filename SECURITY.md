# Безопасность

SplitBox обрабатывает выбранные пользователем APK/архивы и использует Root/Shizuku только при явном выборе и предоставленном доступе. Сетевое разрешение отсутствует; файлы и история не отправляются на сервер.

Особенно важны ошибки ZIP traversal/limits, shell injection, OBB destination, подписи/наборы splits, session correlation и ложный success. Для воспроизведения используйте собственные тестовые APK и отдельное устройство/эмулятор.

Если у опубликованного GitHub репозитория доступно **Security → Report a vulnerability**, используйте приватный канал. Владельцу репозитория следует включить Private vulnerability reporting при публикации. До появления настроенного приватного канала не публикуйте exploit, приватные APK или чувствительные логи в обычном issue; сначала согласуйте безопасный способ передачи с maintainer.

Приложите минимальное описание, затронутую версию, Android/ROM, backend и безопасные шаги воспроизведения. Signing keys, пароли и персональные данные не нужны для отчёта. Обычные ошибки интерфейса/совместимости можно отправлять через bug report template.

Статус покрытия и непроверенные устройства описаны в [VERIFICATION.md](docs/VERIFICATION.md). Исходный код проходит адресные проверки и тесты; полный независимый security audit не заявляется.
